#### Architecture Flow
```
┌─────────────────────
│  MariaDB (Moodle)  │ (Source: ข้อมูลการลงทะเบียน)
│  vw_student_enrol  │
└──────┬──────────────
       │ Extract with Hash
       ▼
┌─────────────────────────────────────
│   StudentSyncService               │
│                                     │
│  • calculateHash() - MD5 checksum  │
│  • detectChanges() - Compare hash  │
│  • processInserts() - Add new      │
│  • processUpdates() - Update exist │
│  • processDeletes() - Remove old   │
│  • processByFaculty() - Batch sync │
└────────┬────────────────────────────
         │
         ▼
   ┌──────────────┐
   │  Oracle DB  │
   │  WBSC.      │
   │  STUDENT_   │
   │  ENROLLMENT │
   └──────────────┘
```

#### Business Logic
```
1. Extract data from MariaDB view with hash calculation
2. Compare hashes between source and target
3. Classify records:
   - INSERT: New records (hash not exists in target)
   - UPDATE: Changed records (hash different)
   - DELETE: Removed records (not in source)
   - UNCHANGED: Same records (hash matched)
4. Process each operation type in batches (500 records)
5. Support faculty-based sync (ทีละคณะ)
6. Log statistics per faculty and overall
```

#### Oracle Table Structure (In Development)
```sql
-- Target Table
CREATE TABLE WBSC.STUDENT_ENROLLMENT
(
  ID                  NUMBER,
  CAT_TYPE            VARCHAR2(255),
  CAT_FACULTY         VARCHAR2(255),
  CAT_TERM_ID         NUMBER,
  CAT_TERM            VARCHAR2(255),
  COURSE_ID           NUMBER,
  COURSE_SHORTNAME    VARCHAR2(255),
  COURSE_FULLNAME     VARCHAR2(1000),
  USER_ID             NUMBER,
  USERNAME            VARCHAR2(255),
  IDNUMBER            VARCHAR2(255),
  FIRSTNAME           VARCHAR2(255),
  LASTNAME            VARCHAR2(255),
  EMAIL               VARCHAR2(255),
  ENROL_STATUS        VARCHAR2(50),
  ENROL_DATE          DATE,
  DATA_HASH           VARCHAR2(32),      -- MD5 hash for change detection
  CREATED_AT          DATE DEFAULT SYSDATE,
  UPDATED_AT          DATE DEFAULT SYSDATE,
  CONSTRAINT pk_student_enrol PRIMARY KEY (ID)
);

-- Indexes
CREATE INDEX idx_student_course ON STUDENT_ENROLLMENT(COURSE_ID, USER_ID);
CREATE INDEX idx_student_term ON STUDENT_ENROLLMENT(CAT_TERM_ID);
CREATE INDEX idx_student_hash ON STUDENT_ENROLLMENT(DATA_HASH);
CREATE INDEX idx_student_idnumber ON STUDENT_ENROLLMENT(IDNUMBER);
```

#### Incremental Sync Strategy
```
Phase 1: Calculate Hash
- Generate MD5 hash from key fields:
  MD5(course_shortname + username + enrol_status)

Phase 2: Detect Changes
- Compare source hash vs target hash
- Classify: INSERT / UPDATE / DELETE / UNCHANGED

Phase 3: Process by Operation Type
- INSERT: Batch insert new records
- UPDATE: Batch update changed records
- DELETE: Mark as deleted or remove
- UNCHANGED: Skip (log count only)

Phase 4: Statistics & Logging
- Total records processed
- Per-faculty breakdown
- Operation counts (INSERT/UPDATE/DELETE/UNCHANGED)
- Duration and performance metrics
```

### Teacher Sync - CLI Commands
```bash
# Preview data without executing
php spark teacher:sync --dry-run

# Execute sync
php spark teacher:sync

# Force sync (ignore recent sync check)
php spark teacher:sync --force

# Verbose output
php spark teacher:sync --verbose

# Combined options
php spark teacher:sync --force --verbose
```

### Student Sync - CLI Commands 🆕
```bash
# Preview changes without executing (dry-run)
php spark student:sync --dry-run

# Execute incremental sync (default)
php spark student:sync

# Full sync (truncate and reload all)
php spark student:sync --full

# Sync specific faculty only
php spark student:sync --faculty=1

# Force sync (ignore recent sync check)
php spark student:sync --force

# Verbose output
php spark student:sync --verbose

# Combined options
php spark student:sync --faculty=1 --force --verbose
php spark student:sync --full --verbose

# Examples:
# Sync only Faculty 1 (incremental)
php spark student:sync --faculty=1

# Full reload of all data
php spark student:sync --full

# Preview what would change
php spark student:sync --dry-run
```

### Student Sync - Cron Job 🆕
```bash
# Run incremental sync every 30 minutes
*/30 * * * * cd /path/to/wbsc-app && php spark student:sync >> /var/log/student-sync.log 2>&1

# Run full sync daily at 3:00 AM
0 3 * * * cd /path/to/wbsc-app && php spark student:sync --full

# Run faculty-based sync (rotate faculties)
0 */4 * * * cd /path/to/wbsc-app && php spark student:sync --faculty=1
0 */4 * * * cd /path/to/wbsc-app && php spark student:sync --faculty=2

# Run every hour during business hours (8 AM - 5 PM)
0 8-17 * * * cd /path/to/wbsc-app && php spark student:sync
```
